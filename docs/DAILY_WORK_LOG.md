## 项目定位与当前状态

暂定题目：《基于嵌入式 Linux 的便携式离线语音转写终端设计与实现》。

面向近距离、单人轮流讲话，计划实现按键录音、离线中文转写和屏幕显示。应用主体采用 C11；底层调用 sherpa-onnx C API 与预训练 SenseVoice INT8 模型。使用现成模型不等于自行训练或提出新模型，项目贡献集中于应用架构、采集与存储、异常处理、部署和实验评价。

截至目前，Ubuntu 上文件识别、定时录音、回车控制录音和模型常驻多轮转写已完成。ARM 开发板验证、物理按键、屏幕、扩展 PCB 和整机尚未完成。前端预处理对照实验尚未开始。导师对新题目及硬件形式的最终意见待确认。

代码仓库：https://github.com/Laijinghao/offline-speech-terminal

## 2026年9月19日：离线识别基础、真实录音与麦克风采集

### 1. 建立 Windows 与 Ubuntu 开发环境

**原因：** 现有 Ubuntu 位于 VMware，需要在 Linux 中真正编译运行，避免只在 Windows 跑样例就误认为完成嵌入式部署。

**实现：** 用户启动并登录虚拟机，安装并启动 SSH 服务，配置公钥连接。项目放在 Ubuntu 的 ~/offline_asr 和 Windows 的毕设/offline_asr。通过官方发布包准备 sherpa-onnx v1.13.8 与 SenseVoice INT8 模型，记录下载来源、许可证和校验信息。缺少的构建工具在项目 tools/ 下准备。

**结果：** 两个系统分别编译运行；这仍然是 x86 电脑环境，不是 ARM 主板验证。密码不写入仓库，模型和依赖二进制不提交。

### 2. 完成 C 语言文件转写程序

**原因：** 先确认音频输入、模型调用、文字输出和计时链路可用，再加入实时设备输入，便于定位问题。

**实现：** main.c 处理参数、输入输出检查与退出码；wav.c 解析 RIFF/WAV 和 PCM16 采样；asr.c 配置 SenseVoice、调用 C API、复制结果并释放资源。输入限制为 16 kHz、单声道、16 位 PCM，最长 60 秒。输出采用独占创建，拒绝覆盖已有文件。

**验证：** WAV 格式边界、命令行错误和真实模型样例通过；还在隔离网络命名空间中运行推理，验证识别过程无需联网。官方 5.592 秒样例在 Ubuntu 中解码约 0.59 秒，模型加载约 1.50 秒。

### 3. 用个人录音排查开头缺字

**原因：** 官方样例通过不代表个人录音采集正确，需要区分采集问题与模型识别错误。

**实现：** 将第一条 MP3 转换为标准 WAV，检查格式和开头，并增加 500 ms 前置静音做对照。用户回听后确认原录音没有录到“今天”，因此不是模型漏掉了已存在的两个字。重新录制第二条，使用 user_voice_20260919_02.wav。

**结果：** 第二条时长 10.032 秒，识别约 1.089 秒、加载约 1.417 秒，用户确认完整文字。MP3 转换存在解码警告，仍保留在记录中，不宣称源音频完全无损解码。第一条保留作为排错记录，第二条作为完整录音测试依据。

### 4. 增加 Linux 麦克风定时录音

**原因：** 从“已有文件识别”推进到真实输入，形成录音到文字的闭环。

**实现：** record.c 通过 ALSA 采集 PCM，支持设备选择、三秒倒计时、时长限制、超时和取消。完整录音先写同目录临时文件，再独占发布最终 WAV；采集失败或取消时清理临时文件。run_mic.sh 串联录音和 asr_demo。

**排错：** 首次录音峰值仅 852/32768，只输出“行”。检查发现 Ubuntu 输入音量为 42%，调整到 100% 后重录，峰值升至 17247/32768，输出与测试句一致。这支持输入音量过低是失败的重要原因；两次重新录音并不是严格的同音频对照实验。

**验证：** 自动测试扩展到 7 项，包括合成 PCM 逐采样核对和 SIGINT 清理。真实 10 秒录音解码约 1.05 秒、加载约 1.37 秒。此时仍每次运行重新加载模型。

### 5. 性能测试与硬件候选分析

**原因：** 判断模型运行开销，给后续选板提供依据。

**实现：** 在 8 个虚拟 CPU 环境下，以第二次完整录音测试 1、2、4、8 线程。RTF 分别约为 0.195、0.102、0.055、0.051。4 线程以后收益减小，但这只是有限样本观测，不能推广为所有设备的最佳线程数。

**限制：** 通过通用 CPU 跑分换算 ARM 推理速度只能作为粗略讨论，不能证明 RK3566、RK3588 或树莓派一定够用。既有硬件推算段落仍需完整核算、核实来源，最终购买决定以目标板实测与实际报价为准。当前不承诺 NPU 部署。

## 2026年9月20日：代码同步、按键交互、模型常驻及阶段验收

### 1. 处理两套目录的 Git 同步

**原因：** Ubuntu 最初是拷贝目录，后来初始化 Git 后，其工作树与远端存在差异；不能为了同步而丢失模型和个人录音。

**实现与结果：** 比较本地与远端差异，恢复缺失的受版本控制文件，更新忽略规则和过时文档。检查两个误创建的 --output、--wav 文件均为零字节后删除。results/ 规则更新后原文件自动被忽略，不代表文件被删除。GitHub 连接不稳定时使用 Git bundle 传递提交。

**以后怎么做：** 先检查 git status 和差异；干净且无分叉时使用 git pull --ff-only。存在本地修改时先判断或备份。不要把 git reset 加全目录 restore 当作日常同步命令，它会丢弃受版本控制文件的本地修改；git clean -fdx 可能删除被忽略的模型和录音，不能使用。前面的同步经验不意味着这些命令普遍安全。

### 2. 实现“回车录一句”

**原因：** 固定 10 秒录音不能适应实际说话长度，需要用户自行开始和结束。

**实现：** 为已有 record_wav 增加 --interactive，通过 poll 检查终端输入，不重写 ALSA 采集。回车开始、再回车结束，写入实际收到的采样数；最长 60 秒，Ctrl+C 取消。run_sentence.sh 复用 asr_demo 完成转写。

**验证：** 使用伪终端和合成音频检查开始、停止、自动截止、取消及非终端拒绝。用户实际录制 27.159750 秒，模型加载 4.495497 秒、解码 3.235575 秒。开头出现的额外字符需要回听核对，不能直接认为全文准确。

### 3. 将模型初始化移到主循环之前

**原因：** 单句入口每次启动 asr_demo，都会支付模型加载成本；多轮交流应复用模型。

**实现：** asr.c 增加模型创建、单轮转写和模型销毁接口，保留旧 asr_transcribe 兼容入口。新增 asr_session，父进程初始化模型一次，每轮 fork/exec 已有录音程序，录音完成后创建新的识别流并释放该轮流。这样复用模型但不复用上一句的识别状态。

每次启动以 mkdtemp 建立独立会话目录，每轮编号生成 WAV/TXT，拒绝覆盖已有文件。录音、WAV 解析或 TXT 保存失败后提示重试，继续下一轮；q 加回车退出，Ctrl+C 结束。底层推理库崩溃或系统 OOM 不属于可恢复的普通单轮错误。

**验证：** 真实模型在同一进程内重复识别，中途注入坏 WAV、预置 TXT 冲突和录音失败，确认后续轮次仍成功、已有内容不变。Windows 原文件识别回归也通过。测试驱动使用 Python 模拟终端，但产品程序仍是 C，用户运行不需要编写 Python。

### 4. 真实麦克风多轮验收

**原因：** 自动测试不能代替真实设备、用户按键和讲话过程。

**结果：** 两个会话分别完成 8 轮与 3 轮，共 11 轮成功流程。首次加载分别为 1.537401 秒和 1.441547 秒。最近三轮音频长 17.701、9.229、20.915 秒，录音结束后处理约 1.871、0.967、2.268 秒。用户以 q 正常退出。

**计时解释：**
- model_load_seconds：每个会话首次加载一次。
- audio_seconds：实际音频长度。
- decode_seconds：模型处理该段音频的耗时。
- RTF：decode_seconds / audio_seconds，不包含首次加载或等待用户。
- post_capture_seconds：录音子进程结束后的读取、识别与结果保存。
- round_seconds：还包括等待用户开始和讲话时间，不能当作纯识别耗时。
- status=ok：程序流程成功，不等于识别文字完全正确。

其中一轮 round_seconds 为 307.079271 秒，但音频仅 60 秒、录音后处理 8.240754 秒，不能写成模型推理用了五分钟。

## 常用入口

在 Ubuntu 的 ~/offline_asr 中运行：

```sh
sh build_linux.sh
sh run_sample.sh
sh run_mic.sh 10
sh run_sentence.sh
sh run_session.sh
```

分别用于构建验证、官方文件样例、定时录音、单轮回车录音、多轮模型常驻录音。常驻模式是当前推荐演示入口。

源码模块：src/main.c 为文件入口，src/record.c 为采集，src/asr.c 为模型接口，src/session.c 为会话管理，src/wav.c 为格式处理。测试文件位于 tests/；README 为使用入口，docs/ 为详细记录。模型、库和录音不在 GitHub 仓库里，新机器需要自行准备依赖。
