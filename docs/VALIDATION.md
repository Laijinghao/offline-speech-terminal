## 个人录音第一次测试（2026-09-19）

- 原始文件：上级目录 `标准录音 1.mp3`，保留未修改。ffprobe显示48kHz、双声道，容器时长6.9708秒。
- 本地转换：FFmpeg输出16kHz、单声道、PCM16 WAV，保存为 `recordings/user_voice_20260919_01.wav`，实际采样时长6.936秒。仅转换后的录音通过本机虚拟网络传入用户Ubuntu，未上传外部服务。
- 转换出现 `Header missing` / `Invalid data found when processing input` 解码错误；FFmpeg最终退出码为0并输出WAV。不能据此保证原始音频全部无损解码，时长差也不能单独证明丢失了具体词语。需要人工回听，必要时重新导出WAV录音。
- Ubuntu C程序退出码0；模型加载1.425947秒，识别0.761875秒，RTF=0.109844。
- 转写结果保存在 `results/user_voice_20260919_01.txt`，耗时在同名前缀的 `_metrics.txt` 中。
- 结果以“是星期六”开头。用户最初表示说了“今天是星期六”，后经回听确认原始录音并未录到“今天”；因此这两字不应计作模型漏识别。完整录音逐字标注尚未完成，暂不计算全文字符错误率。
- 第一条个人录音的输入到文字流程已验证；内容准确性与原始音频完整性仍待确认。

### 开头漏字复核

- 仅给转换后的WAV增加500ms前置静音，未改变语音采样内容，再用相同模型和参数运行，结果仍以“是星期六”开头。
- 对照文件为 `recordings/user_voice_20260919_01_pad500.wav`，输出和耗时在 results/ 同名前缀文件中；时长7.436秒，加载1.463522秒，识别0.787562秒，RTF=0.105912。
- 因此500ms前置静音未修复这一条样本；不能仅由此确定根因，更不能自动在输出中补写“今天”。
- 原转换WAV前2秒另存为 `recordings/user_voice_20260919_01_first2s.wav`，用于人工回听确认“今天”是否存在于解码后的音频中。
- 用户已回听并确认：原始录音没有录到“今天”。这条记录归类为采集开头不完整，不归因于模型。
