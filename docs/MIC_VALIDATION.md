# 麦克风采集阶段验证（2026-09-19）

## 实现与环境

C11 + ALSA 实现 16kHz、单声道 PCM16 录音，定时 1～60 秒；通过现有 sherpa-onnx C API 转写。Ubuntu 20.04 VMware 虚拟机使用 Ensoniq 虚拟声卡，用户使用头戴式耳机；耳机连接方式及宿主机具体路由尚未单独确认。尚未验证 ARM 开发板。

录音成功后才发布最终 WAV；目标文件已存在则拒绝覆盖。取消或采集失败清理临时文件。发生采集溢出时直接报错，不隐瞒音频缺口。模型目前每轮重新加载，不属于流式字幕。

构建需要 libasound2-dev。当前开发虚拟机将对应开发包解压在项目 tools/ 内，并链接系统现有 libasound.so.2；新机器可正常安装开发包。不要提交 tools/ 或依赖二进制。

## 用户实录结果

用户在看到 RECORDING 后说“现在我开始测试 123321”。

| 项目 | 首次 | 调整输入音量后 |
| --- | --- | --- |
| 录音时长 | 10 秒 | 10 秒 |
| 采样数 | 160000 | 160000 |
| 峰值 / 32768 | 852 | 17247 |
| 模型加载 | 1.489705 秒 | 1.368010 秒 |
| 解码 | 1.036214 秒 | 1.049867 秒 |
| RTF | 0.103621 | 0.104987 |
| 输出 | 行。 | 现在我开始测试123321。 |

检查发现 Ubuntu 输入未静音，但输入音量为 42%（-22.50dB）。将默认模拟麦克风输入音量调整到 100%（0dB），用户再次录音后识别与口述一致。输出音量未调整。两次是重新录制的音频，不能视为同一音频的严格控制实验；结果支持低输入音量是此前失败的重要原因。

这是单句功能验证，不代表整体准确率、嘈杂环境表现或实时字幕能力。峰值未达到满量程并不能排除更上游设备已经失真。个人 WAV 和原始结果仅保留本地。
